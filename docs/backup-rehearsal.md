# 합성 DB 암호화 백업·복원 리허설

운영 DB를 대상으로 하지 않는 TECH 검증이다. 실제 운영 백업의 경로·권한·보관기간·키 담당·복원 절차는 기존 [백업 정책 초안](privacy/backup-recovery.md)과 미결 질문의 승인이 필요하다.

## 실행

Docker Desktop과 Python이 있는 저장소 폴더에서 실행한다. 호스트 리허설 스크립트는 표준 라이브러리만 사용한다.

```powershell
docker build -f Dockerfile.prototype -t coriops-nexus-prototype:local .
python scripts/verify_backup.py
```

서버·운영 `.env`를 읽지 않고, 무작위 임시 비밀번호·전용 내부 Docker 네트워크·새 합성 DB만 사용한다. PostgreSQL 16 클라이언트 이미지와 age 1.3.2-r1을 고정했다. 앱·DB 컨테이너에는 복호화 개인키를 연결하지 않는다.

## 검증 순서

1. 전용 DB에 합성 계정·혈액 접수·결과·접속기록을 만든다.
2. pg_dump를 표준 age 공개키 암호화로 넘긴다. 평문 덤프 파일을 만들지 않는다.
3. 잘못된 키와 변조 파일의 복원이 거부되는지 확인한다.
4. 복원은 명시적 허용과 `_restore_test` 이름을 확인하고, 사용자 테이블·시퀀스가 있는 대상은 거부한다.
5. 암호문을 격리된 임시 경로에 복사해 인증을 먼저 확인한다. 같은 암호문을 다시 스트리밍 복호화해 빈 대상에 `pg_restore --single-transaction`으로 복원한다. 인증되지 않은 스트림을 먼저 DB에 확정하지 않는다.
6. 복원된 혈액 결과·처리 계정과 접속기록 해시 체인을 확인한다.
7. 해당 Compose 프로젝트와 이번에 만든 임시 경로만 정리한다. 삭제 전 절대 경로가 저장소의 리허설 디렉터리 안인지 확인한다.

출력 JSON에는 건수·검증 성공 여부만 남으며 이름·차트번호·검사값·비밀번호·개인키를 출력하지 않는다. 키와 암호문은 `outputs/backup-rehearsal/`의 이번 임시 폴더에만 만들고 종료 시 정리한다. 다른 컨테이너·네트워크·볼륨은 정리 대상으로 삼지 않는다.

## 운영 전 남은 확인

- 담당자가 승인한 비동기화 로컬 백업 경로·매체 및 최소 권한의 전용 DB 계정.
- 서버에는 공개 recipient만 배치하고 개인키는 담당자가 별도 보관·복원 시 주입하는 절차.
- 실제 업무 PC의 HTTPS·접속 대역·역할과 보관 정책 승인.
- 실패 확인·수동 복구·실제 복원 시간 측정과 담당자 재현. 이번 리허설은 무인 운영·법적 적합성을 확인한 결과가 아니다.
