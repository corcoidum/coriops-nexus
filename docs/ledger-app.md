# 조직검체·CLO·Stool 장부 앱 (DB 저장)

**DB가 원본이다.** 입력은 앱 화면에서 하고 PostgreSQL에 쌓는다. 엑셀은 ① 기존 장부 가져오기, ② 수기 장부와의 대조, ③ 지정 원내 폴더 출력에만 쓴다. 출력한 엑셀을 고쳐 DB로 되돌리지 않는다(A13).

> DB 저장 모드에서는 **개인 계정 로그인과 접속기록이 항상 켜진다**(아래 '로그인·접속기록'). 원장 결재 전에는 합성 자료로만 시험한다.

## 화면

| 화면 | 하는 일 |
|---|---|
| 조직검체 장부 `/dashboard` | ＋새 검사 접수(조직검사·CLO·Stool), 오늘 수탁기관 인계(3자·병 수 대조), 결과 입력, 원장 지시, 재검 완료. 종류 탭(전체·조직검사·CLO·Stool), 검색(차트번호·이름·접수번호·결과코드), 50건 단위 페이지 |
| 원장 지시 대기 | 과거 장부에서 가져온 결과도 여기에 모인다. 행을 골라 하나씩 지시하거나, **여러 건을 체크해 '재검 불필요(사유)'를 한 번에** 기록한다. 하나라도 기록할 수 없으면 전부 취소된다 |
| 재검 대상 | 기한 경과 → 30일 이내 → 이후 순서. 재검 시행일을 기록하면 종결 |
| 엑셀 가져오기·출력 `/ledger/excel` | 가져오기·대조 미리보기 → 신규만 저장, 지정 폴더 출력, 보관기간 경과 후보 표시 |

목록은 이름 가운데를 가린다(예: `가****일`). 입력 대상을 확인하는 오른쪽 상세에서만 전체 이름을 보인다.

## 로그인·접속기록 (DB 저장 모드에서 항상 켜짐)

| 항목 | 동작 (`config/security.yaml`) |
|---|---|
| 계정 | 개인 계정만. 아이디는 영문 소문자·숫자 3~30자 |
| 비밀번호 | argon2id 해시만 저장, 10자 이상, 아이디 포함 금지. 새 계정·초기화 후 첫 로그인에서 반드시 변경 |
| 잠금 | 연속 5회 실패 → 30분 잠금. 실패 메시지는 아이디가 있는지 드러내지 않는다 |
| 세션 | 서버에 저장(토큰은 해시만). 15분 미사용 또는 12시간 경과 시 자동 로그아웃. 쿠키 HttpOnly·Secure·SameSite=Strict |
| 위조 요청 | 모든 변경 요청에 세션별 CSRF 값 + 다른 사이트 Origin 거부 |
| 권한 | 역할(원장·원무·간호·개인정보 책임자)별 업무 허용표. 허용되지 않은 접근은 403 + 권한 거부 기록. 표는 [가정]이며 Q01에서 확정 |
| 계정 관리 | 개인정보 책임자만. 역할·사용 중지·비밀번호 초기화 시 대상의 로그인 즉시 끊김 + 권한 이력. 마지막 책임자 삭제·자기 역할 축소 금지 |

**접속기록**에는 아이디·일시·접속지(IP)·업무·정보주체(차트번호)·결과가 남는다. 목록에 보인 환자는 `목록 조회`(이름 가림), 오른쪽 상세는 `상세 조회`(전체 이름), 접수·결과·지시·인계·가져오기는 환자별 `등록/변경/엑셀 가져오기` 행으로 남는다. 엑셀 출력은 건수와 함께 한 행이다.

- 기록은 추가만 된다. UPDATE·DELETE·TRUNCATE는 DB 트리거가 거부한다.
- 각 행은 직전 행의 SHA-256 해시를 이어받는다. **접속기록 점검** 화면이 전체 체인을 다시 계산해 고쳐지거나 지워진 순번을 알려준다.
- 10분 안에 서로 다른 환자 50명 초과 상세 조회·변경은 대량 조회 경고로 표시한다([가정] Q13).
- 점검 완료 시 그 시점의 마지막 순번·해시와 의견을 함께 저장한다.
- 로그인 실패에는 입력한 아이디 원문을 남기지 않는다(등록된 계정이면 계정 UUID만). 검색어·셀 값·비밀번호도 남기지 않는다.

### 처음 계정 만들기 (원장 = 원장 + 개인정보 책임자)

```sh
docker compose -f docker-compose.prototype.yml --profile ledger run --rm ledger \
  python -m app.manage create-staff --username wonjang --display-name 원장 --roles DOCTOR,PRIVACY_OFFICER
```

임시 비밀번호는 화면에서 두 번 입력받는다(명령행에 쓰지 않는다). 이후 직원 계정은 원장이 **계정·권한 관리** 화면에서 만든다.

## 기존 엑셀 가져오기 (Biopsy·CLO·Stool 모두)

1. `/ledger/excel`에서 기존 장부 파일(.xlsx, 5MB 이하)을 올린다. 암호가 걸린 파일은 원내 PC에서 해제한 **사본**을 올린다.
2. 미리보기에서 시트별로 **신규 / 동일 / 차이 / 엑셀 누락 / 제외 / 결과 검토** 건수를 본다. 이 단계에서는 아무것도 저장하지 않는다.
3. **신규 N건 DB에 저장**을 누르면 신규 행만 저장한다. 차이 행은 덮어쓰지 않는다.

| 규칙 | 내용 |
|---|---|
| 시트 | 탭 이름 `Biopsy`·`CLO`·`Stool`(대소문자 무시). `분석 대시보드` 등 다른 탭은 읽지 않는다 |
| 열 | `config/ledger_app.yaml`의 헤더 사전으로 찾는다. 이름이 다르면 별칭을 추가한다. 차트번호·수진자명·검사일이 없으면 시트를 건너뛴다 |
| 저장하지 않는 열 | 비고란·연락처 등은 값을 읽어도 저장·표시하지 않고 헤더 이름만 보고한다 |
| 조직검사 결과 | `TA#2(L), H#1` 코드 표기만 저장한다(A11). 문장형은 저장하지 않고 **결과 표기 확인**으로 원장 지시 대기에 올린다 |
| CLO·Stool 결과 | `+`, `-`, `양성`처럼 20자 이내 판정만 저장한다. 문장은 검토 대상 |
| 특이소견 | 위 검체의 `HP-/Neu++/…`만 Sydney 등급으로 저장한다 |
| 중복 | 같은 종류 안의 접수번호, 없으면 차트번호+검사일(+검사종류)로 찾는다 |
| 이름 충돌 | 같은 차트번호에 다른 이름이면 그 행을 가져오지 않는다 |
| 과거 행 | 위탁일이 없어도 과거 날짜면 인계 완료로 본다. 오늘 행만 인계 대기로 남는다 |

## 수기 장부 병행 검증

병행 기간에는 수기 엑셀을 평소처럼 쓰고, 주기적으로 같은 파일을 다시 올려 미리보기만 확인한다.

- **차이**: DB와 엑셀의 접수번호·결과보고일·결과·검체수량·특이소견·검사위치·위탁일 중 다른 항목 이름을 보여준다. 어느 쪽이 맞는지 확인해 바로잡는다.
- **엑셀 누락**: 엑셀에 있는 기간 안인데 DB에만 있는 행이다(앱에만 입력하고 수기 장부에 빠진 건).
- **신규**: 수기 장부에만 있는 행이다. 확인 후 저장하면 DB에 들어간다.

차이·누락이 연속으로 0이 되면 원장과 협의해 수기 입력을 멈춘다.

## 엑셀 출력 (지정 원내 폴더만)

- **지정 폴더에 엑셀 저장**은 DB 전체를 `조직검체장부_YYYYMMDD_HHMMSS.xlsx` 새 파일로 저장한다. 시트는 Biopsy(기존 17열)·CLO·Stool이고, 끝에 `재검 예정일`·`재검 상태` 열이 붙는다.
- 저장 위치는 환경변수 `CORIOPS_EXPORT_DIR` 하나뿐이다. 화면에서 경로를 고를 수 없다.
- 다음 경우는 저장하지 않는다: 폴더 미설정·상대 경로·없는 폴더·링크, OneDrive·Google Drive·Dropbox·CloudStorage가 경로에 들어간 폴더, 같은 이름의 파일이 이미 있을 때.
- `=`로 시작하는 값은 수식이 아닌 글자로 저장한다. 출력 기록(시각·파일명·건수)은 DB에 남는다.
- **원장 결정 필요:** 기존 설계의 'Export 없음'(P12)을 이 조건부 출력으로 바꾸는 것을 승인받아야 한다. 출력 파일의 보관기간·파기도 정해야 한다.

## 보관기간

`config/security.yaml`의 보유기간 설정(종결 후 5년, 상태 `REQUIRES_OWNER_AND_LEGAL_REVIEW`)을 **그대로 유지**한다. 앱은 기간이 지난 종결 건을 '보관기간 경과 후보'로 세어 보여줄 뿐 자동으로 지우지 않는다. 파기는 [보유·파기 초안](privacy/retention-policy.md)의 원장 승인 절차를 따른다.

## 실행 — 원내 PC

1. 저장소 폴더에서 `.env.example`을 `.env`로 복사해 두 값을 채운다.
   - `CORIOPS_DB_PASSWORD`: 무작위 24자 이상
   - `CORIOPS_EXPORT_HOST_DIR`: 엑셀 출력 지정 폴더(절대 경로, 클라우드 동기화 폴더 금지)
2. 실행한다. 처음 시작할 때 Alembic이 DB 테이블을 만든다.

```sh
docker compose -f docker-compose.prototype.yml --profile ledger up -d --build
```

브라우저: <http://127.0.0.1:8766/dashboard> (이 PC에서만 접속). 중지: `docker compose -f docker-compose.prototype.yml --profile ledger stop`

DB 자료는 Docker 볼륨 `ledger-data`에 남는다. `down -v`는 볼륨을 지우므로 쓰지 않는다. 백업은 [백업 초안](privacy/backup-recovery.md)을 따른다.

## 구조

| 파일 | 역할 |
|---|---|
| `app/modules/endoscopy_pathology/manual_dashboard.py` | 업무 서비스(접수·인계·결과·지시·재검·가져오기·출력·보관기간) |
| `ledger_db.py` | 저장소 계약. `MemoryStore`(합성 시연) / `PostgresStore`(version 검사로 동시 수정 방지, 한 업무 = 한 트랜잭션) |
| `excel_io.py` | 엑셀 읽기(메모리, 셀 값 없는 오류 보고)·출력 workbook |
| `migrations/` | Alembic 스키마. 업그레이드·다운그레이드·재업그레이드를 시험한다 |
| `app/ledger_server.py` | 시작 시 마이그레이션 → DB 주소 외 발신 차단 → 서버 |
| `app/kernel/auth.py`·`access_log.py`·`routes_auth.py` | 로그인·세션·권한·계정 관리, 추가 전용 해시 체인 접속기록·점검 |
| `app/manage.py` | 오프라인 초기 계정 생성 |

이 장부 스키마(`ledger_*` 테이블)는 실사용을 위한 실용 모델이다. `ontology/coriops.yaml`의 정식 PathologyRequest 모델과의 통합은 Q17 결정 후 진행한다.
