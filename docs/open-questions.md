# 확인할 질문과 [가정]

2026-10-21. 답변이 없는 항목은 승인되지 않았다. **Phase 1 Gate 질문은 config 기본값으로 대체하지 않는다.** 이 문서의 결정 상태를 바꾸고 관련 YAML·문서 스냅샷을 함께 갱신한다.

## 이번 대화에서 확정된 사항

- A01: R03·R04·R06 즉시 생성 + 기한 경과 판정. E2E 수정 승인.
- A02: 검체별 부분 수신, 전체 유효 결과 후 완료, 정정 보고서 새 회차, 재확인·재안내, 기존 F/U 원장 재검토 승인.
- A03: 로그 식별자 연결·백업 30일 잔존 적정성은 원장 확인 대상으로 남김. 잔존 자체를 승인한 것은 아님.

## 추가 설계 [가정]

- Q11: 진료일 기한은 기준일 제외 N번째 진료일 마감, `now > due_at`부터 지연. URGENT는 당일 마감이며 마감 후 입력이면 즉시 기한 도달. 화면에 즉시 강조하고 30분 스케줄만 기다리지 않는다.
- Q12: `instruction_note`·각 사유는 업무 메모만 허용한다. UI 경고와 길이 제한은 임상 소견 입력을 완전히 막지 못하므로 교육·점검이 필요하다.
- Q13: 대량 조회 경고는 10분간 서로 다른 환자 50명 초과를 초안으로 둔다. 원장 확인 후 조정한다.
- Q14: 환자 URL의 chart_no·이름·검색값은 프록시·서버 기본 로그에 남기지 않는다. 화면 접근은 서비스 AccessLog UUID로 기록한다.
- Q15: 일반 정정은 새 회차를 열고 유효한 원장 확인·안내를 유지할 수 있지만, 보고서 정정은 재확인·재안내를 강제한다. 보존할 증거는 상태 머신 문서에 명시한다.

Q16 근거: [openpyxl 공식 reader 소스](https://openpyxl.readthedocs.io/en/stable/_modules/openpyxl/reader/excel.html)의 read()는 worksheet 처리 전에 read_strings()를 호출한다. read_only 옵션도 이 단계를 건너뛰지 않는다. 이 관찰에 따라 '내부 파서도 무시 값 0건 읽기'라는 보장은 제안하지 않는다.

다음 행동: Q01·Q02·Q04·Q06·Q09·Q16 답변 → 문서·YAML 갱신 → Phase 0 승인 → 명시적 Phase 1 실행 승인. 답변 대기 중 다음 Phase로 자동 진행하지 않는다.
