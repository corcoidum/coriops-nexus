# 확인할 질문과 [가정]

최종 갱신: 2026-10-22. 답변이 없는 항목은 승인되지 않았다. **Phase 1 Gate 질문은 config 기본값으로 대체하지 않는다.** 이 문서의 결정 상태를 바꾸고 관련 YAML·문서 스냅샷을 함께 갱신한다.

## 이번 대화에서 확정된 사항

- A01: R03·R04·R06 즉시 생성 + 기한 경과 판정. E2E 수정 승인.
- A02 (2026-10-21): 검체별 부분 수신, 전체 유효 결과 후 완료, 정정 보고서 새 회차, 재확인·재안내, 기존 F/U 원장 재검토 승인. 이후 A04에 따라 씨젠의 일반 업무 경로에서는 부분 결과를 접수하지 않는다. 부분 수신 구조의 v0.1 유지 여부는 재검토한다.
- A03: 로그 식별자 연결·백업 30일 잔존 적정성은 원장 확인 대상으로 남김. 잔존 자체를 승인한 것은 아님.
- A04 (2026-10-22 사용자 설명): 현재 씨젠은 환자별 모든 조직검체 결과가 나와야 공개하므로 직원도 전체 결과가 공개된 뒤 확인·전달할 수 있다. 일반 경로는 전체 결과 수신으로 정의한다. 개별 검체 coverage·정정 이력 필요성과 부분 결과 접수 기능은 구분한다.
- A05 (2026-10-22 사용자 설명): 사무장과 지정 직원 1명이 수시로 결과를 확인하고 필요한 내용을 원장에게 보고한다. 모든 결과가 원장 보고 대상은 아니다. 직원의 확인 기록과 원장의 임상 확인·지시를 별도 행위로 구분하며, 미보고 결과의 안내·F/U·종결 근거는 Q17에서 확인한다.
- A06 (2026-10-22 추가 설명): 조직검체 결과를 보고 환자별 다음 내시경 시점을 결정하는 사람은 원장이다. A05의 직원 확인·별도 보고 루틴과 원장의 임상 판단 주체를 구분한다. 시스템이 시점을 자동 결정하지 않는다. 원장 지시를 언제·어디에 기록하고 환자에게 안내하는지는 추가 확인한다.
- A07 (2026-10-22 새 요청): 원내에서 씨젠 병원 계정으로 매일 결과를 조회하고 지정 Excel 양식을 자동 갱신하는 웹앱을 원한다. 이전의 포털 자동 조회 금지·외부 통신 0·Excel Export 없음에서 범위를 바꾸려는 의도로 기록한다. [ADR-005](decisions/ADR-005-seegene-excel-integration.md)에 제안을 작성했으며, 로그인 방식·자동화 가능성·원문 저장 범위는 미확정이다. ID/PW는 채팅으로 받지 않는다.
- A08 (2026-10-22): 실제 확인 주소는 `https://srms.seegenemedical.com/main.do`. 사용자 제공 열 17개를 `app/modules/endoscopy_pathology/ledger_mapping.yaml`에 순서 그대로 기록했다. 조직검사결과·검사위치는 현재 원문을 읽어 병원 약어로 수기 기입한다. 원문 전체를 Excel에 복사하는 업무로 해석하지 않는다.
- A09 (2026-10-22): 사용자가 약어는 나중에 정리해 제공하고 다음 단계로 진행하도록 지시했다. 약어를 기다리지 않고 **합성 데이터 전용 Excel 프로토타입**을 구현한다. 미등록 약어는 검토 대기이며 실제 수집·임상 자동 해석·실데이터 전환 승인을 뜻하지 않는다.
- A10 (2026-10-22): 사용자는 복잡한 자동 수집보다 직접 결과 입력과 첫 대시보드부터 시작하기를 원한다. 씨젠 자동 로그인·약어 변환은 보류하고 [합성 수동 대시보드](manual-dashboard.md)를 먼저 시연한다. 자유로운 짧은 입력은 사전 등록이 필요 없다. 원장 지시의 수기 날짜 기록만 제공하며 실제 업무 절차·정식 개인정보 정책을 이 시연으로 확정하지 않는다.

## 추가 설계 [가정]

- Q11: 진료일 기한은 기준일 제외 N번째 진료일 마감, `now > due_at`부터 지연. URGENT는 당일 마감이며 마감 후 입력이면 즉시 기한 도달. 화면에 즉시 강조하고 30분 스케줄만 기다리지 않는다.
- Q12: `instruction_note`·각 사유는 업무 메모만 허용한다. UI 경고와 길이 제한은 임상 소견 입력을 완전히 막지 못하므로 교육·점검이 필요하다.
- Q13: 대량 조회 경고는 10분간 서로 다른 환자 50명 초과를 초안으로 둔다. 원장 확인 후 조정한다.
- Q14: 환자 URL의 chart_no·이름·검색값은 프록시·서버 기본 로그에 남기지 않는다. 화면 접근은 서비스 AccessLog UUID로 기록한다.
- Q15: 일반 정정은 새 회차를 열고 유효한 원장 확인·안내를 유지할 수 있지만, 보고서 정정은 재확인·재안내를 강제한다. 보존할 증거는 상태 머신 문서에 명시한다.

Q16 근거: [openpyxl 공식 reader 소스](https://openpyxl.readthedocs.io/en/stable/_modules/openpyxl/reader/excel.html)의 read()는 worksheet 처리 전에 read_strings()를 호출한다. read_only 옵션도 이 단계를 건너뛰지 않는다. 이 관찰에 따라 '내부 파서도 무시 값 0건 읽기'라는 보장은 제안하지 않는다.

현재 Ontology와 config/rules.yaml은 이전 검토안이다. A05/A06의 직원 확인·원장 판단 구분과 A07의 수집·Excel 범위가 반영된 확정 모델이 아니다. Q17/Q18 답변 뒤 업무·통신·출력·저장 범위를 정하고 YAML·상태도·Rule·E2E·개인정보 대응표를 함께 갱신한다.

현재 진행: A10 범위의 [합성 수동 대시보드](manual-dashboard.md)를 구현·검증한다. 정식 앱 Phase Gate와 Q17/Q18의 실제 수집·권한·원장 지시·개인정보 정책은 유지한다. 약어 보류를 이유로 이 독립 프로토타입을 중단하지 않으며, 실제 로그인·환자자료 수집으로 임의 확대하지 않는다. Q18의 자동 수집 질문은 지금 화면을 확인하는 데 선행 조건이 아니다.
