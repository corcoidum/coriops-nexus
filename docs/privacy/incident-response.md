# 개인정보 사고 대응 절차 초안

**법률 자문이 아닌 초안, 원장 결재·확인 필요.** 사고 책임자·대체자·연락체계는 원장이 작성하며 실제 전화번호를 저장소에 넣지 않는다.

1. 탐지: 비정상 조회·로그 해시 불일치·분실·백업 실패를 발견하면 시각·장비·계정 UUID·현상만 기록한다. 실데이터 화면을 외부 서비스에 업로드하지 않는다.
2. 억제: 원장 승인 또는 사전 승인된 긴급 절차에 따라 해당 계정 세션 폐기·권한 중지·LAN 연결 격리를 수행한다. 로그·증거를 지우거나 서버를 임의 초기화하지 않는다.
3. 보존: 최소 담당자만 로컬 격리 매체에 증거를 보관한다. 접근·수집 행위도 기록하고 원본과 분석용 사본을 구분한다.
4. 평가: 원장이 범위·유출 여부·영향·통지/신고 필요성과 법정 시한을 현행 공식 기준·전문가와 확인한다. 이 초안에서 시한을 추측해 고정하지 않는다.
5. 복구: 원인 제거·비밀번호/키 교체·백업 검증·최신 파기 재적용 후 제한된 PC에서 확인하고 재개한다.
6. 사후: 원인·조치·재발 방지·교육·책임자 승인과 완료시각을 남긴다. 임시 자료의 보유·파기도 정한다.

앱 장애 시에는 승인된 수기 업무대장으로 전환하고, 복구 후 담당자가 누락 업무를 대조한다. AI·외부 분석 자동 전송·자동 의료 판단은 사용하지 않는다.
