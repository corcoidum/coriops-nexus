# 접속기록 점검 절차 초안

**법률 자문이 아닌 초안, 원장 결재·확인 필요.** PRIVACY_OFFICER 개인 계정으로 월 1회 점검을 제안한다. 주기·담당·대체자는 원장이 지정한다.

1. 기간·직원 UUID·환자 UUID로 화면 조회한다. 개인정보 URL·검색값은 일반 서버 로그에 남기지 않는다. 점검 조회도 AccessLog VIEW로 남긴다.
2. 마지막 sequence/hash를 고정하고 hash chain·독립 checkpoint를 대조한다. 승인된 segment 만료도 대조한다.
3. 대량 조회, 근무 외 시간, 반복 로그인 실패·잠금, IP 거부, 권한 변경, 인쇄, 파기를 확인한다. 초기 대량 기준은 10분·서로 다른 환자 50명 초과 [가정]이며 자동 징계·의료 판단을 하지 않는다.
4. 점검 결과 CHECKED 또는 INVESTIGATE, 점검 구간·필터·최종 hash·후속 조치만 기록한다. 환자 이름·연락처·결과 원문을 점검 메모에 쓰지 않는다.
5. 이상 시 책임자가 직원에게 업무 사유를 확인하고 계정 중지·권한 회수·사고 대응 여부를 결정한다. 보고와 법적 신고 판단은 incident-response 문서로 넘긴다.

기록 필수 항목 5개는 사용자 식별자, 접속일시, 접속지, 처리 환자 참조, 수행업무다. 환자 업무가 없는 로그인/거부는 patient_ref=null 사유를 outcome_code로 설명한다. 로그를 파일 Export하는 기능은 v0.1에 없다. 화면 인쇄는 PRINT 기록과 인쇄물 관리가 필요하다.
