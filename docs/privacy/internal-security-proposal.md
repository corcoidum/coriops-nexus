# 내부 보안 유지 방법 — 검토와 단계별 제안

**법률 자문이 아닌 초안, 원장 결재·확인 필요.** 작성 2026-10-24. 기존 [대응표](compliance-matrix.md)·[내부 관리계획 부속](internal-plan-addendum.md)은 정식 앱의 설계 기준이다. 이 문서는 **지금 실제로 쓰는 Excel·종이 장부**부터 앱 시범 운영까지를 같은 순서로 정리한다. `[확인]` 표시는 현장 상태를 아직 모르는 항목이다.

## 1. 현재 위험 진단 — Excel·종이 장부 운영 기준

조직검체 장부 1행에는 차트번호·이름·나이·성별, 조직검사 결과 코드, Sydney 등급이 함께 있다. 이 조합은 진단 정보가 포함된 개인정보이므로 파일 하나가 유출되어도 영향이 크다.

| 위험 | 일어나는 경로 | 영향 |
|---|---|---|
| Excel 파일 무단 열람·복사 | 암호 없는 파일, 공용 PC 바탕화면·공유 폴더 `[확인]` | 수백 명의 결과가 한 번에 노출 |
| 클라우드 자동 동기화 | 바탕화면·문서 폴더의 OneDrive 백업, 휴대폰 사진의 클라우드 자동 업로드 | 원내 밖 서버에 사본이 남음 |
| 화면 캡처 외부 공유 | 메신저·AI 서비스·이메일로 화면 사진 전송 | 2026-10-24 대화에서 차트번호가 보이는 캡처가 공유됨 |
| 공용 Windows 계정·잠금 없음 | 자리 비운 사이 열람 `[확인]` | 누가 봤는지 알 수 없음 |
| 씨젠 포털 계정 공유 | 비밀번호 메모, 퇴사자 계정 유지 `[확인]` | 외부에서 결과 조회 가능 |
| 종이 대장 노출 | 접수대 위 펼쳐 둠 | 다른 환자가 볼 수 있음 |
| 백업 없음·평문 USB | 디스크 고장, USB 분실 `[확인]` | 장부 소실 또는 유출 |

## 2. 1단계 — 지금 바로 (비용 없음, 이번 주)

Excel과 종이 장부를 그대로 쓰면서 할 수 있는 조치다. 효과가 큰 순서로 적었다.

1. **Excel 파일에 열기 암호를 겁니다.** 파일 → 정보 → 통합 문서 보호 → *암호 설정* 순서입니다. 이 방식은 파일 자체를 AES로 암호화한다. *시트 보호*는 편집만 막고 내용은 그대로 읽히므로 대신 쓸 수 없다. 암호는 원장과 담당자만 알고 메모로 남기지 않는다.
2. **저장 위치를 고정합니다.** 원내 PC의 로컬 지정 폴더 한 곳에만 두고 OneDrive·Google Drive·바탕화면 동기화 폴더에서 뺀다. 이 앱 설계의 백업 경로 금지 목록(`config/security.yaml`)과 같은 원칙이다.
3. **외부 공유 규칙을 정합니다.** 메신저, AI 서비스, 이메일로 장부 화면을 보낼 때는 다음을 지킨다.
   - 차트번호·이름 열을 **삭제**하거나 헤더와 가짜 값만 보낸다.
   - 펜으로 가린 사진은 일부 글자가 보일 수 있어 충분하지 않다.
   - 휴대폰으로 모니터를 찍지 않는다. 사진이 클라우드에 자동으로 올라가기 때문이다.
4. **Windows 계정을 사람별로 나눕니다.** 화면 보호기 잠금은 5~10분으로 맞추고, 자리를 뜰 때 `Win + L`을 누르는 습관을 들인다. 자동 로그인은 끈다.
5. **디스크를 암호화합니다.** Windows Pro라면 BitLocker, Home이라면 기기 암호화 지원 여부를 확인한다 `[확인]`. 복구 키는 원장이 PC와 분리해 보관한다.
6. **씨젠 계정을 정리합니다.** 개인별 계정을 발급받을 수 있는지 씨젠에 확인하고, 공유 계정이라면 퇴사·담당 변경 때 비밀번호를 바꾼다.
7. **종이 대장을 보관합니다.** 사용하지 않을 때는 잠금 서랍에 두고 접수대 위에 펼쳐 두지 않는다.
8. **백업을 만듭니다.** 암호가 걸린 Excel 사본을 주 1회 전용 외장 매체에 복사하고 잠금 보관한다. 평문 사본을 USB에 들고 다니지 않는다.

## 3. 2단계 — 이 앱을 원내에서 시범 운영할 때 (실데이터 넣기 전)

지금 시연 앱(`docs/manual-dashboard.md`)은 합성 자료·메모리 전용이다. 실제 장부를 옮기려면 아래가 **먼저** 있어야 한다.

| 통제 | 내용 | 정식 설계 대응 | 시연 앱 현재 |
|---|---|---|---|
| 원내 전용 접속 | 서버 1대, 업무 PC IP 대역만 허용, 인터넷 차단 | P7·P13 | 127.0.0.1만 게시, Python 발신 차단 ✅ |
| 개인 로그인 | 직원별 계정, argon2id, 5회 실패 잠금, 15분 미사용 종료 | P2·P3·P4·P6 | 적용 ✅ (DB 모드, 역할표는 Q01 가정) |
| 접속기록 | 누가 언제 어떤 환자를 조회·변경·검색했는지 | P8 | 적용 ✅ 추가 전용·해시 체인·점검 화면 (외부 체크포인트·DB 계정 분리는 후속) |
| 영구 저장 | PostgreSQL, 앱 계정은 기록 삭제 불가 | ADR-001 | PostgreSQL 저장·Alembic ✅ (DB 계정 분리는 후속) |
| 결과 최소 저장 | 결과는 코드·등급만, 판독문 문장 입력 차단 | A11 | 코드 형식만 허용 ✅ |
| 화면 노출 최소화 | 이름 가운데 가림, 오류 화면에 입력값 미표시, 캐시 금지 | P12 | 적용 ✅ |
| 위조 요청 차단 | CSRF 토큰, 출력 escape | P1 일부 | 적용 ✅ |
| 암호화 통신 | Caddy 원내 인증서로 HTTPS | P1·ADR-003 | 없음 (localhost 시연) |
| 엑셀 출력 제한 | 지정 원내 폴더 하나, 새 파일만, 출력 기록, 링크·클라우드 경로 거부 (A13, P12 개정 필요) | P12 | 적용 ✅ |

**병행 기간 원칙:** 앱 시범 운영 중에도 Excel 장부는 1단계 통제를 유지한다. 두 곳에 같은 정보가 있는 기간을 정해 두고, 끝나면 하나를 원장 결재로 정리한다.

## 4. 3단계 — 실데이터 정식 운영 전 (원장 결재)

- 개인정보 처리방침·내부 관리계획에 조직검사 결과 코드 저장 범위(A11)를 반영한다. [체크리스트](processing-policy-checklist.md)
- 보유기간과 파기 방법을 정한다(Q06). Excel 사본과 종이 대장 정리 방법도 포함한다.
- 매월 접속기록을 점검한다. 대량 조회 경고 기준(Q13)도 함께 정한다.
- 암호화 백업을 만들고 복원 리허설을 1회 이상 한다. [백업 초안](backup-recovery.md)
- 직원 교육과 비밀유지 서약: 캡처 공유 규칙, 판독문 문장 입력 금지, 자리 비움 잠금.

## 5. 규모에 맞게 미루는 것

의원 한 곳, 직원 몇 명 규모에서는 아래 항목을 2단계 필수 조건으로 두지 않는다. 접속기록과 개인 로그인이 먼저다.

- 접속기록 해시 체인·월별 segment·외부 체크포인트(P8 위변조 탐지)
- DB 함수로만 상태 변경(SECURITY DEFINER)
- 파기 ledger의 복원 후 재파기 자동화

위 항목은 실데이터가 쌓이고 운영이 안정된 뒤 3단계 이후에 붙인다. 생략하는 것이 아니라 순서를 미루는 것이며, 위 1·2단계 통제를 대신하지 않는다.
