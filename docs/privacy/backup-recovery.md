# 백업·복원 설계 초안

**법률 자문이 아닌 초안, 원장 결재·확인 필요.** Q06/Q09 승인 전 구현·운영 확정이 아니다.

## 키 보관 충돌의 제안

GPG 대칭키 무인 암호화는 서버가 매일 비밀키에 접근해야 하므로 '서버에는 키 없음'과 충돌한다. age 공개키 방식이면 서버는 공개 recipient만 가지고 일일 암호화할 수 있고 복호화 개인키는 원장이 오프라인에 보관한다. 암호문 무결성 검증을 제공하는 정식 age 도구를 사용하고 독자 암호화를 만들지 않는다. [age 공식 저장소](https://github.com/FiloSottile/age)

공개 recipient가 원장 개인키에 대응하는지는 초기 복원 리허설로 확인한다. recipient 변경은 승인·Audit 대상이다. 개인키 두 번째 복구 매체의 보관자·봉인·분실 대응은 Q09에서 정한다. Caddy CA 개인키와 백업 개인키를 혼용하지 않는다.

## 일일 작업 제안

- backup DB 계정의 `pg_dump`를 파이프로 age에 전달하고 평문 dump 파일을 만들지 않는다. pipefail을 적용해 덤프 실패를 암호화 성공으로 처리하지 않는다.
- 승인된 로컬 볼륨의 임시 암호문 `.partial` → 암호화 성공·hash/크기 검증 후 atomic rename. 불완전 산출물은 격리하고 실패를 화면에 표시한다.
- 최대 보관일은 30일 제안. 파일명·mtime만 신뢰하지 않고 생성시각 manifest를 검사하며 복사로 만료를 연장하지 않는다. 만료 정리가 실패하면 보안 실패로 보고한다.
- 경로는 정규화·symlink/junction 해소 후 승인 로컬 volume인지 검사한다. OneDrive/Google Drive/Dropbox/CloudStorage 경로·alias·reparse 우회를 거부한다. 단순 문자열 검색만으로 동기화 여부를 완전히 알 수 없으므로 설치 시 운영 확인을 추가한다.
- 작업 주체는 ADMIN 세션이 아닌 제한된 서버 스케줄 작업이다. 앱에서 임의 경로·쉘 명령을 받지 않는다. 비밀정보를 명령행 로그에 남기지 않는다.

## 복원 리허설

별도 로컬 격리 환경 → 개인키 일시 연결 → 암호문 변조 검증 → PostgreSQL 16 복원 → 최신 파기 ledger 재적용 → FK/건수·로그 체인·샘플 workflow 점검 → 개인키 연결 해제. 출력은 합성 데이터와 비식별 결과 건수만 보관한다. plaintext SQL을 stderr/터미널에 출력하지 않는다.

TECH 증거는 암호화 파일이 평문이 아님, 잘못된 키/변조 거부, 복호화·실제 DB restore, 만료·경로 우회 시험이다. OPS 증거는 원장 키 접근·매체 위치·수동 복원 재현이다. LEGAL 증거는 최대 30일 잔존 허용·파기 정책 승인이다. RPO 24시간, RTO는 미확정 제안이며 실측 후 결정한다.
