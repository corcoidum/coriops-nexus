# 규칙 L01~L05 — 생성·기한·해소 (Stage B, A17)

제목·담당·우선순위·일수는 `config/rules.yaml`, 진료일·수령 시각은 `config/clinic.yaml`이 원천이다. 이 문서의 숫자는 설명이며 코드에 넣지 않는다. 이전 검토안 R01~R08(환자 안내 포함)은 git 이력과 [이전 정식 모델](archive/ontology-0.1-design.2.yaml)에 있다(D11, A12).

규칙은 **상태·기한·누락만** 본다. 결과 코드의 의미·중요도, 재검 필요 여부·간격을 판단하지 않는다(AGENTS 절대 규칙 2, Q19).

| 규칙 | 생기는 조건 | 기한(due_at) | 저절로 닫히는 때 | 담당 · 우선순위 | 회차(anchor) |
|---|---|---|---|---|---|
| L01 인계 누락 | 조직검사·Stool이 인계 대기이고 지금이 기한을 지남(당일 인수·당일 인계, A16) | 시행날짜의 수령 시각(월화목금 15:00, 수토 11:00). 그날 수령이 없으면 다음 수령일의 수령 시각 | 인계 기록 | 간호 · HIGH | 시행날짜 |
| L02 결과 지연 | 결과 대기이고, 위탁일(RUT는 시행날짜) 다음날부터 센 진료일이 기준을 넘김: 조직검사·Stool 2, RUT 1 | 기준을 넘는 첫 진료일 전날의 마지막 시각. 화면의 '지연'과 같은 순간 | 결과 입력 | 원무 · NORMAL | 위탁일(또는 시행날짜) |
| L03 원장 지시 대기 | 결과가 입력됐고 원장 지시 없음. 과거 엑셀에서 가져온 건은 제외(화면 배지만) | 회신날짜 다음 1번째 진료일의 마지막 시각 | 원장 지시 기록 | 원장 · NORMAL | 회신날짜 |
| L04 재검 30일 이내 | 원장이 정한 재검일까지 1~30일 | 재검일의 마지막 시각 | 재검 완료, 또는 재검일 도래(L05로 넘어감). 사람이 [확인 완료]로 닫는다 | 원무 · NORMAL | 재검일 |
| L05 재검 도래·경과 | 재검일이 오늘이거나 지났는데 완료 기록 없음 | 재검일의 마지막 시각(다음날 0시부터 기한 지남) | 재검 완료 | 원무 · HIGH | 재검일 |

담당 역할은 권한표 Q01과 같은 [가정]이다.

## 할 일의 상태

| 상태 | 뜻 | 누가 |
|---|---|---|
| OPEN | 열림. `now > due_at`이면 기한 지남 | 규칙 |
| AUTO_RESOLVED | 조건이 풀려 저절로 닫힘(인계·결과·지시·재검 완료, 재검일 변경) | 규칙 |
| DONE | 확인 완료 | 사람(기록 계정이 남음) |
| DISMISSED | 해당 없음. **사유 필수**(120자 이내) | 사람 |

- **중복 키** `{규칙}:{대상 종류}:{대상 id}:{회차}`는 한 번만 저장한다. 몇 번을 다시 돌려도 같은 키는 새로 만들지 않는다.
- 사람이 닫은 키(DONE·DISMISSED)는 조건이 남아 있어도 다시 열지 않는다.
- 원장이 재검일을 바꾸면 회차가 달라진다. 새 할 일이 생기고 예전 할 일은 저절로 닫힌다.
- 제목은 설정의 고정 문구만 쓴다. 할 일·실행 기록에 이름·차트번호·결과를 넣지 않는다.

## 언제 도나

- **업무 기록 직후**(접수·인계·결과·지시·재검 완료·가져오기): 바뀐 검사만 다시 본다(`SUBJECTS`).
- **화면을 열 때**: 마지막 전체 실행에서 5분(`full_run_interval_minutes`)이 지났으면 전체를 돈다(`ALL`). 수령 시각이 지나는 것처럼 시간이 흘러야 생기는 일을 잡는다. 별도 상시 스케줄러는 두지 않는다.
- **동시 실행**: PostgreSQL advisory lock(7_340_012)으로 한 번에 하나만 돈다.
- **실행 기록**(`rule_runs`): 시각·범위·설정 해시·후보·생성·자동 해소 건수·오류 종류를 남긴다.
- **실패해도 업무 기록은 되돌리지 않는다.** 실패(FAILED)와 예외 종류만 남기고 서버 로그에도 적는다. 오류 문구에는 입력값이 섞일 수 있어 남기지 않는다.

## 시험 (`tests/prototype/test_rules_tasks.py`, `test_tasks_db.py`)

- 규칙마다 생김·안 생김·저절로 닫힘을 본다.
  - L01: 14:59 안 생김, 15:01 생김, 인계 후 닫힘. 수요일 11:00 수령, 휴진일 다음 수령일
  - L02: 8일 × 하루 3시점 모두에서 화면의 '지연' 표시와 할 일 유무가 같다(조직검사·RUT)
  - L04→L05 전환, 재검일 변경 시 새 회차
- 같은 시각으로 10번 돌려도 할 일 수가 그대로다. 고정 시계로 두 번 만든 결과가 같다.
- PostgreSQL에서는 생성·자동 해소·사람이 닫기, 상태·우선순위·역할 CHECK, 설정에서 빠진 규칙 끄기를 본다.
- 규칙을 일부러 틀리게 바꾸면 시험이 실패하는지 확인했다(지연 경계, 자동 해소, 닫힌 키 재생성, 가져온 건 제외).
