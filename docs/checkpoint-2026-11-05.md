# 2026-11-05 단계별 구현 기록

PR #11을 CI 성공 확인 후 병합했다(기준 main `1064fa3`). 합성 메모리 시연과 DB 저장 모드는 구분한다. 실데이터 운영 승인은 포함하지 않는다.

## 담당별 할 일

- `/`의 장부별 카드는 유지하고 내 역할의 할 일 건수와 `/tasks` 연결을 추가했다.
- `/tasks`: 내 역할(복수 역할 합집합)·전체 역할, 기한 지남·오늘·이후 대기·처리됨. 기한 지남은 `now > due_at`이며 오늘 목록과 중복되지 않는다. 처리됨은 설정의 최근 기간에 한정한다.
- 업무명·담당·기한·상태·원본 상세 링크만 보이며 환자정보를 Task에 복제하지 않는다.
- 담당 역할만 확인 완료·해당 없음 처리가 가능하다. 해당 없음은 기존 120자 사유 규칙을 쓴다. 처리자 계정은 서버에서 정하고 검사 상태를 바꾸지 않는다.
- DB 처리는 접속기록과 한 트랜잭션이며 동시·반복 처리는 409로 거부한다. 전체 보기 권한이 다른 역할의 처리 권한을 주지 않는다.

## 혈액 접수·DB 저장

- `/lab?new=1`에서 접수일·차트번호·성명·선택 성별/나이·검사 분류를 접수한다. 접수 요청 UUID의 재제출은 기존 접수를 반환한다.
- DB 모드에서도 `/lab`·`/lab/paper`·`/critical`을 조립한다. `lab_cases`는 공통 환자 FK·등록/입력/표기/보고/확인 계정·시각·version을 저장한다. 새 DB에는 합성 혈액 기록을 자동 생성하지 않는다.
- 결과·표기·보고·확인은 로그인 계정을 사용하고, 업무와 접속기록을 함께 commit/rollback한다. 간호는 접수·조회만 가능하며 결과·보고·확인은 기존 권한표를 유지한다.
- 같은 차트번호의 이름 불일치, 다른 건의 접수번호 재사용, 낙관적 갱신 경합은 거부한다. DB 초기화 버튼은 없고 서버에서도 거부한다.
- PostgreSQL 전체 시험 545건 통과 후 입력 검증·마이그레이션 왕복 시험을 추가했다. 실제 Chrome에서 합성 접수→AST H·Anti-HCV Neg→관리자 표기→원장 보고→확인을 실행하고 앱 재시작 후 기록이 남는 것을 확인했다.

## 실행 방법

```powershell

```
