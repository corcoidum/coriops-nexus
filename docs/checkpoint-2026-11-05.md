# 2026-11-05 단계별 구현 기록

PR #11을 CI 성공 확인 후 병합했다(기준 main `1064fa3`). 합성 메모리 시연과 DB 저장 모드는 구분한다. 실데이터 운영 승인은 포함하지 않는다.

## 담당별 할 일

- `/`의 장부별 카드는 유지하고 내 역할의 할 일 건수와 `/tasks` 연결을 추가했다.
- `/tasks`: 내 역할(복수 역할 합집합)·전체 역할, 기한 지남·오늘·이후 대기·처리됨. 기한 지남은 `now > due_at`이며 오늘 목록과 중복되지 않는다. 처리됨은 설정의 최근 기간에 한정한다.
- 업무명·담당·기한·상태·원본 상세 링크만 보이며 환자정보를 Task에 복제하지 않는다.
- 담당 역할만 확인 완료·해당 없음 처리가 가능하다. 해당 없음은 기존 120자 사유 규칙을 쓴다. 처리자 계정은 서버에서 정하고 검사 상태를 바꾸지 않는다.
- DB 처리는 접속기록과 한 트랜잭션이며 동시·반복 처리는 409로 거부한다. 전체 보기 권한이 다른 역할의 처리 권한을 주지 않는다.

## 실행

```powershell
docker compose -f docker-compose.prototype.yml --profile dashboard up -d --build dashboard
```

합성 시연은 <http://127.0.0.1:8765/>이며 재시작 시 초기화된다. DB 모드의 설정·초기 계정은 [장부 앱 사용법](ledger-app.md)을 따른다.
