# 실행 전 명세 충돌 검토

최종 갱신: 2026-10-22, Phase 0. **확정사항**은 원문 요구 또는 이번 대화의 명시 답변이다. **제안**은 승인 전 설계안이며 구현 허가가 아니다. **사용자 확인 필요**는 Phase 1 Gate를 막는 도메인·개인정보 결정이다.

## 2026-10-22 실제 업무 확인 — 기존 검토안보다 우선

- **확정사항(A04):** 사용자 설명에 따르면 현재 씨젠 결과는 환자별 모든 조직검체 결과가 나온 뒤 공개된다. 따라서 일반 경로는 전체 공개 후 접수·확인이며, 부분 결과 조기 전달을 전제하지 않는다.
- **확정사항(A05):** 사무장과 지정 직원 1명이 수시로 확인하고 필요한 내용을 원장에게 보고한다. 모든 결과를 원장에게 보고하는 절차는 아니다.
- **기존 설계와의 충돌:** 전건 PhysicianReview, 전건 R03 원장 확인 Task, 원장 확인만을 근거로 한 REVIEWED·종결 guard는 실제 업무와 맞지 않아 재검토한다. 아래의 이전 모델·버전 제안은 확정 구현 명세가 아니다.
- **제안:** 직원의 업무상 확인과 원장의 임상 확인·지시를 별도 기록으로 구분한다. 앱은 특이 여부·보고 필요성·임상 분류를 자동 판정하지 않는다.
- **사용자 확인 필요(Q17):** 원장 미보고 결과의 환자 안내·F/U·종결 근거와 보고 필요 기준. 확인 전 원장 확인을 직원 확인으로 대체하거나 종결 우회 전이를 추가하지 않는다.

## 2026-10-22 추가 요청 — 씨젠 수집·Excel 갱신

- **확정사항(A06):** 환자별 다음 내시경 시점은 원장이 결과를 보고 결정한다. 직원의 별도 보고 여부와 임상 결정 주체는 별개다. Q17의 결정 주체는 해소됐고 기록·안내·종결 절차는 남았다.
- **변경 의도(A07):** 씨젠을 매일 자동 조회해 지정 Excel에 정리하는 원내 웹앱을 원한다. 기존 금지 목록만 인용해 요청을 거절하지 않고 통신·출력 범위를 재설계한다.
- **충돌:** 기존 외부 통신 0(P13), Export 없음(P12), 포털 자동 조회 금지와 양립하려면 명세 변경이 필요하다. 원문 저장·PDF 파싱 필요 여부는 아직 확인되지 않았다.
- **제안:** [ADR-005](decisions/ADR-005-seegene-excel-integration.md)의 원내 수집 작업자·목적지 제한·허용 열 매핑·중복/정정 검사·수동 열 보존·원장 지시 수동 입력.
- **확인 필요(Q18):** 로그인 전 URL, 지정 양식의 열·수식·원문 필요 범위, 원내 실행/편집 환경. 인증정보·실데이터를 채팅으로 요청하지 않는다. 현재 수행한 것은 공개 자료 확인과 설계이며 실제 로그인·수집·배포는 수행하지 않았다.

## 보고서 버전 제안의 상세 규칙

- 의뢰의 전체 검체 목록을 발송 시 고정한다. `BOTH`도 [가정] 의뢰 1건이며 검체 부위로 구분한다.
- 이전 모델은 보고서·검체의 다양한 연결을 `ReportSpecimen`으로 표현했다. A04의 현재 씨젠 일반 경로는 전체 공개 후 접수다. 검체별 연결 구조의 필요성과 부분 수신 기능의 필요성을 구분해 후자를 재검토한다.
- `logical_report_key`는 한 보고서 계열을 식별한다. 정정본은 동일 의뢰·동일 계열, 직전 버전의 `supersedes_id`와 사유를 가져야 하며 원본을 덮어쓰지 않는다. 같은 직전 버전에 두 갈래 정정은 금지한다.
- 유효 결과 집합은 계열별 최신 버전의 검체 coverage 합집합이다. 모든 발송 검체가 포함되어야 `RESULT_RECEIVED`다. 미도착·검체 부적합·재채취를 정상 수신으로 임의 간주하지 않는다.
- 정정본은 그 계열의 coverage 전체를 명시한다. 확인 완료 뒤 coverage 감소는 접수 보류 후 원장 정정 절차로 `SHIPPED`까지 되돌려 처리한다. 정상 수신인 척 종결하지 않는다.
- 원장 확인은 당시 유효한 **모든** 버전 UUID를 `ReviewReport`와 `report_set_hash`로 고정한다. 새 보고서 접수와 review가 경합하면 의뢰 잠금 후 최신 hash 재검증한다.
- 정정본 접수는 SYSTEM의 임상 판단이 아니다. 수신 권한자가 기록하고, 새 WorkCycle로 재확인 Task를 만든다. 임상 분류·F/U 날짜는 복사해 확정하지 않는다.
- 기존 F/U 계획은 `RECONFIRM_REQUIRED`로 표시하고 원래 날짜는 유지한다. 기존 임박·지연 R07·R08도 원장 확인 전 숨기지 않는다. 재확인 시 원장이 유지·수정·취소하며 사유를 남긴다.
- 부분 결과 조기 원장 전달은 현재 씨젠 일반 업무에 해당하지 않는다(A04). 직원 확인 이후 원장 보고·후속 처리 기준(Q17)과 예외(Q02)가 남아 구현 준비 완료로 처리하지 않는다.

## 과도한 선행 구현을 막는 경계

WorkCycle은 재작업 구분자, SubjectReference는 polymorphic FK 보완, 보고서 연결 테이블은 실제 검체 coverage다. 범용 프로세스 디자이너, 이벤트 버스, KG, AI Agent 실행기는 추가하지 않는다. 커널 Engine은 등록된 객체·guard만 호출하며 모듈을 import하지 않는다.

## 추가 발견 — P14와 지정 파서의 요구 해석 충돌

**확정사항:** 원본 디스크 미저장·ignore 값 DB/로그/preview 미저장은 요구사항이다. **관찰:** [openpyxl 공식 reader 소스](https://openpyxl.readthedocs.io/en/stable/_modules/openpyxl/reader/excel.html)는 sharedStrings를 먼저 읽는다. **제안:** 앱의 선택·매핑·저장 금지와 파서 내부 읽기를 구분하고 허용 필드 전용 입력을 검토한다. **사용자 확인 필요:** Q16. 파서 내부에서도 무시 값 읽기 0을 요구한다면 현재 openpyxl 기본 읽기 경로로 충족한다고 말할 수 없다. 요구를 임의로 완화하지 않고 구현 전에 멈춘다.
