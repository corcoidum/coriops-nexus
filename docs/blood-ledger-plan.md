# 검진 혈액검체 결과 대장 — 계획 초안

작성일: 2026-10-25. 상태: **L0 답변 반영, L1·L2 합성 프로토타입 구현.** 실제 결과 파일·씨젠 접속·실데이터 전환은 미착수.

씨젠에 위탁한 검진 혈액검체 결과를 확인해 정리하는 대장을 조직검체 대장과 **별도로** 만든다. 조직검체 대장(`endoscopy_pathology`)은 지금 방식대로 계속 진행하며, 두 작업이 서로의 코드·설정·시험을 바꾸지 않게 나눈다.

[roadmap](roadmap.md)의 v0.2 "Lab 파일 import"·v0.3 "검진 F/U"를 앞당기는 요청이다. 이번 계획은 조직검체 대장과 같은 **합성 자료 전용 프로토타입** 수준에서 시작하며, 정식 Phase Gate·실데이터 전환·씨젠 자동 조회(ADR-005 보류)를 승인한 것이 아니다.

## 조직검체 대장과 다른 점

| 항목 | 조직검체 대장 | 혈액검체 대장 (예상, 확인 필요) |
|---|---|---|
| 결과 형태 | 서술형 소견 → 병원 약어로 수기 기입 | 항목별 수치 + 단위 + 참고치 + 씨젠 H/L 표시 |
| 한 행 단위 | 접수 1건 | 수진자 1명의 전체 결과 1행 (L02) |
| 약어 사전 | 필요(Q19 대기) | 불필요. 결과란에 이상 항목만 `항목 값 H/L`로 적음 (L04) |
| 주요 위험 | 결과 누락, 원장 F/U 지시 누락 | 이상치·critical value 보고 누락, 재검 안내 누락, 항목 누락 |
| 후속 판단 | 다음 내시경 시점 = 원장 | 재검·추가검사·상담 필요 여부 = 원장 (시스템이 판단하지 않음) |

시스템은 씨젠이 표시한 H/L·위급치를 그대로 옮길 뿐, 참고치와 비교해 정상/이상·위급치를 새로 판정하지 않는다.

## 확정 사항 — 2026-10-25 사용자 답변

- L01: ~~13열~~ → **2026-10-26 원내 실제 서식(A18)으로 변경.** 1행 제목 `혈액병리검체 접수, 인계, 인수 및 회신결과 대장 (일반<6종.9종>/간)`, 2행 12열: 날짜·접수번호·차트번호·성명·성별/나이·분류(일반/간)·접수인(서명)·위탁날짜·인계인(서명)·수령인(서명)·회신날짜·결과. 성별/나이는 `F/52`처럼 한 칸, 서명 3칸은 직원이 직접 적는다. `config/lab_ledger_mapping.yaml`에 기록했다.
- L02: 한 행에 수진자 1명의 내용을 모두 보여준다. 합성 중복 키는 조직검체와 같이 `(접수번호, 차트번호)`다.
- L03: 검사종류는 일반검진6종·일반검진9종·간검진(AFP)·추가b형간염·추가c형간염 5가지다. 목록에 없는 값은 추측하지 않고 배치 전체를 거부한다.
- L04: 결과란은 정상범위 항목을 빼고 이상 항목만 `항목 값 H/L`로 적는다. 예: `AST 52 H, HDL 35 L`.
- L05: critical value(위급치)는 원장에게 보고한다. 프로토타입은 위급치 행의 결과란을 붉은 배경으로 표시하고 `CRITICAL_REPORT` 검토 항목을 만든다. 보고 완료 기록은 L3 대시보드에서 한다.
- L06: 씨젠 결과조회에서 Excel·PDF로 받을 수 있다. L4는 Excel 파일을 대상으로 하고, PDF 자동 판독은 하지 않는다.
- L07 (B07): 검사종류가 여러 개면 쉼표로 구분한다. 예: `일반검진9종, 간검진(AFP)`.
- L08 (B08): 결과 항목이 모두 정상이면 결과란에 `정상`을 적는다. 결과 항목이 아직 없으면(미수신) 빈칸으로 둔다.
- L09 (B09): 위급치는 씨젠 결과에 표시되어 온다. 시스템은 그 표시만 옮기며 원내 기준표로 계산하지 않는다.
- L10 (B10): 결과란 항목명은 원내 약칭 Hb·Glu·CHOL·TG·HDL·LDL·AST·ALT·GGT·Cr 등으로 적는다. 목록(`item_names`)에 없는 이름은 그대로 적고 `ITEM_NAME_UNREGISTERED` 검토 항목을 만든다. 약칭은 사용자가 알려줄 때 목록에 추가한다.
- L11 (B13, 2026-10-26): 추가 B형·C형간염 검사도 분류(일반/간) 칸에 `추가b형간염`·`추가c형간염`으로 적는다. 여러 개면 쉼표로 잇는다(L07).
- L12 (2026-10-26): 성별/나이는 `F/52`처럼 영문 성별/나이로 적는다.

## 병행 작업 규칙

- 코드: `app/modules/screening_lab/`에 새 모듈로 만든다. `endoscopy_pathology`를 import하지 않는다. 공통으로 쓸 코드가 생기면 복사하지 않고 그때 kernel 이동을 따로 제안한다(ADR-004 C1).
- 설정: `config/lab_ledger_mapping.yaml`을 새로 만든다. 기존 `config/ledger_mapping.yaml`은 건드리지 않는다.
- 시험: `tests/prototype/test_lab_*.py`로 분리한다. 기존 75개 시험이 그대로 통과해야 한다.
- 화면: 수동 대시보드에 붙일 경우 별도 경로(`/dashboard/lab`)로 추가하고 기존 `/dashboard` 동작은 바꾸지 않는다.
- 자료: 이름이 `테스트`로 시작하는 합성 자료만 사용한다. 실제 결과지·환자 파일·씨젠 계정은 받지 않는다.

## 구현 — L3 대시보드 혈액 탭

메모리 시연 모드에서 사이드바 **혈액검체 장부**(`/lab`)로 연다. DB 저장 모드에서는 저장소가 없으므로 메뉴·화면을 조립하지 않는다.

| 단계 | 조건 | 직원이 하는 일 |
|---|---|---|
| 결과 미수신 | 결과 항목 없음 | 기다림. L4 파일 가져오기로 채워짐 |
| 원장 보고 대기 | 씨젠 위급치 표시가 있고 보고 기록 없음 | 원장님께 보고 후 **보고한 직원** 기록 |
| 확인 대기 | 결과 수신, 위급치는 보고됨 | 결과란을 장부와 대조 후 **확인한 직원** 기록 |
| 확인 완료 | 확인 기록 있음 | — |

- 위급치는 보고 기록 전에는 확인 완료로 넘어가지 않는다.
- 원장 지시 내용·결과 해석은 받지 않는다. 직원 이름(20자)과 시각만 기록한다.
- 목록은 이름을 가리고 선택한 건만 이름을 보여준다. 조회·변경은 조직검체 장부와 같은 권한(`ledger.view`, `ledger.result`)·접속기록 호출을 거친다.
- 시험: `tests/prototype/test_lab_dashboard.py` 16개 + DB 모드 미조립 1개.

## 두 장부 구분 화면 — A16

| 위치 | 바뀐 점 |
|---|---|
| 첫 화면 `/` | '오늘 할 일'. 조직검체 카드(인계 대기·결과 대기·원장 지시 대기·재검 도래)와 혈액검체 카드(위급치 원장 보고 대기·확인 대기·결과 미수신). 각 줄을 누르면 그 목록으로 간다. 로그인 후에도 여기로 온다 |
| 사이드바 | 오늘 할 일 / 조직검체 묶음(파랑 선) / 혈액검체 · 검진 묶음(청록 선, '위급치 보고' 배지) / 개인정보 |
| 상단 | 장부 이름표(조직검체·혈액검체)와 위급치 알림 `⚠ 위급치 원장 보고 대기 N건`. 누르면 혈액검체 원장 보고 대기 목록으로 간다 |
| 제목 | 각 장부 제목 위에 같은 색 이름표 |

- 첫 화면은 건수만 보여주고 환자 이름·차트번호를 보여주지 않는다. 그래서 접속기록 대상이 아니다.
- DB 저장 모드에서는 혈액검체 묶음·카드·위급치 알림이 나오지 않는다(혈액 탭 미조립).
- 휴대폰 폭(390px)에서 상단 알림은 `⚠ 위급치 N건`으로 줄이고 날짜를 숨긴다. 조직검체 장부 화면의 검색창·표가 넘치는 기존 문제는 이번 범위가 아니다.

## 하지 않는 것

- 수치로 질환·재검 필요 여부·검진 판정을 자동 결정하지 않는다.
